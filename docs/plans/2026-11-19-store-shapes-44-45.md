# Store shapes for amendments 44 and 45

The one copy. The edge and engine lanes drafted these shapes together and
their drafts crossed; the coordinator ruled that this text is the contract
(the edge store lane's final page, plus the coordinator's rulings at the
end). Where a lane's message differs from this file, this file is right.

Times are milliseconds. A record is `{hash, sha256, bytes, key}`.

## Versions

- **States:** `status` is `listed | yanked | taken_down | removed`.
  - `taken_down` is staff's call: harmful, and blocked on devices.
  - `removed` is staff's call: not harmful, not blocked.
- **What the public sees:** `listed` and `yanked` only. The package route
  serves both. A yanked version is never an update offer, only a reinstall.
- **Ordering:** a publish must be later than every existing version, in any
  state. The data file's `newer_rule` says so.
- **Public `VersionInfo`:** `{version, status, published_at, notes, engines,
  yanked, prerelease, key, hash, sha256, bytes, verified: bool,
  verified_at: ms|null, via: "device"|"deploy_key"}`. `verified` is always
  present, and readers require it.
- **Owner and staff add:** `review: {decided, decision:
  "verified"|"declined"|null, reason?, message?, decided_at?}` and `checks`.
  The public never sees "declined".
- **Every version:** `GET /store/v1/plugins/:id/versions?cursor&limit` →
  `{versions, total, next_cursor?, prev_cursor?}`, listed and yanked, newest
  first.
- **One version:** `GET /store/v1/plugins/:id/versions/:version` → that
  `VersionInfo`, else 404 `not_found` (devices: `not_in_store`).

## Cards and detail

- **`PluginCard` gains** `verified` (its `version` is verified) and
  `verified_version: string|null`. `version` is the newest listed version, a
  release before a pre-release, verified or not.
- **Detail:** `versions` is the first page (5), plus
  `versions_next_cursor?`; `package` is `version`'s record; a device installs
  `verified_version` through the one-version route. There is no
  `verified_package`.
- **Catalog:** `?verified=1` narrows it; `?featured=true` holds only plugins
  whose newest version is verified; featuring a plugin without that is 409
  `not_verified`; `?author=<username>` lists one publisher's plugins (an
  unknown username answers an empty list).
- **Categories** carry `count`, the number of listed plugins in each.
- **Store totals:** `GET /store/v1/stats` → `{plugins, verified}`, cached and
  purged with the catalog.

## Publish

- `POST /store/v1/plugins/:id/versions` → `201 {id, version, status:
  "listed", verified: false, checks}`, public at once. The same bytes get the
  same answer.

## Updates and take-downs

- **The update check:** `POST /store/v1/updates`, the ask unchanged
  (`verified_only` per plugin is accepted).
- **Each offer:** the newest listed version newer than the installed one that
  fits `engines` and the pre-release choice: `{id, version, hash, sha256,
  bytes, key, publisher, publisher_id, notes, added, removed, prerelease,
  verified, verified_at}`; `verified_update?` has the same shape, present
  only when the offer is unverified and a newer-than-installed verified
  version exists; `in_review` goes; `blocked[]` is unchanged.
- **The take-down feed:** `GET /store/v1/takedowns?since=<ms>` →
  `{takedowns: [{id, version, reason, at}], now, next_since?}`. Public,
  cached 60 s per colo, purged on each take-down. `since` is exclusive; pages
  hold at most 500, oldest first. Devices poll it every 15 minutes and match
  it against their installs locally, sending nothing about them. The full
  update check stays at 6 hours.

## Deploy keys (44)

- **List:** `GET /store/v1/me/keys` → `{keys: [{key, name, scope,
  created_at, last_used_at, last_used_plugin, expires_at, revoked_at?}]}`.
  `scope` is `{all: true}` or `{plugins: [ids, sorted, unique]}`.
- **Create:** `POST /store/v1/me/keys {key, name, scope, expires?, proof,
  stepUp}` → 201. Session only, with a step-up `for: "deploy_key"`, used
  once. 1–50 ids, each owned now. Refusals: 400 `{error: "invalid_scope",
  ids?}`; 403 `{error: "not_owner", ids}`.
- **Revoke:** `DELETE /store/v1/me/keys/:key` → `{revoked: true}`.
- **Proof v2:** the key signs `"zeron-deploy-key:v2:" + scopeText + ":" +
  key`, where `scopeText` is `*` for all, else the sorted ids joined with
  `,`. v1 is refused. The engine generates the data file (`proof_prefix` v2)
  and the vectors (cases for `*` and for two sorted ids); the edge takes both
  unedited.
- **A signed request may:** `POST /plugins/:id/versions` when the id exists,
  the key's account owns it now, and it is in scope; never a new id (403
  `key_not_allowed`); `GET /me/plugins` (the in-scope plugins it owns);
  nothing else.
- **`/plugin-keys/:key?plugin=`:** verified only when the key is live, the
  plugin is in scope, and the account owns it.
- **Transfer:** no longer revokes keys; ownership is checked at each use.
- **A publish through a key** raises a notice on the author's own devices
  (which key published which version).

## Author and staff

- **Author:** `withdraw` goes; `yank` and `unyank` stay. In `/me/plugins`,
  versions carry `review`, and `listing` is `listed | unlisted | suspended`.
- **Staff queue:** `GET /admin/queue?state=undecided|verified|declined|all`,
  default undecided, oldest first, versions with open reports first. One row
  per plugin: its newest undecided version, saying how many earlier undecided
  versions it stands for; those leave the queue unverified, each recording
  when and by which version it was superseded. Items as amendment 40, plus
  `status`, `review`, `reports`. `base` is the newest verified other version.
- **Staff actions:** `GET /admin/versions/:id/:version`; `POST …/verify`
  (from undecided or declined); `POST …/decline {reason, message}` (from
  undecided); `POST /admin/plugins/:id/versions/:version/take-down {reason}`
  (blocks); `POST …/remove {reason}` (does not block). Each needs the version
  listed or yanked, else 409 `invalid_state`.
- **Audit:** `version.publish` (the author is the actor; `detail {via,
  key}`), `verify`, `decline`, `take_down`, `remove`, `yank`, `unyank`, and
  `plugin.*`, `report.*`, `reservation.*` as now.

## Coordinator's rulings

- **Sorts are honest.** Every sort is exactly its own key, verified or not;
  `verified=1` is a filter; search relevance uses `verified` only to break
  ties. Featured is the vetted shelf.
- **The device's update preference** (`store_updates: "newest" |
  "verified"`, device-wide, with a per-plugin override) defaults to
  `newest`: the newest version is offered and staged, marked when not
  verified, with the newest verified one beside it. One constant.
- **Consent:** installing or updating to an unverified store version always
  asks, even when it asks for nothing new.
- **Agents:** a store install without a version takes `verified_version`
  when there is one; an agent naming an unverified version is refused
  `needs_person` when a verified version exists; an agent never updates an
  installed store plugin.
- **No cap tied to review speed:** the hourly, daily and new-id limits stay
  as they are.
- **Reports** reorder the queue and never hide a plugin by themselves.
