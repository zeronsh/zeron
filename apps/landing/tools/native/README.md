# The hero against the Zeron app

The landing page's app window (`public/hero/`) is the Zeron app's new chat,
redrawn for the web from the app's own code (`apps/zgx`). This folder holds
the rig that draws the real app and diffs the web hero against it, pixel by
pixel and over time. The acceptance test is the diff, not a look.

## What the hero is

- `public/hero/app.js`: mounts the canvas, the springs, the pointer, the
  frame loop (it draws only while a layer moves, and not while off screen).
- `public/hero/wallpaper.js`: WebGL2. The Parallax scenes plugin's Blossom
  scene (`plugins-builtin/parallax-scenes`, art in `public/assets/hero/blossom`)
  drawn into a layer texture, then composited through Zeron's ASCII layer
  shader (`ui/ds/effects.luau` `ascii`, its glyph font `ui/ds/decode.luau`),
  faded by the wallpaper's `fade` and clipped to the page card.
- `public/hero/chrome.js`: Canvas 2D (on the CPU). The title strip, sidebar,
  page card and composer, from `ui/ds/title_bar.luau`, `ui/ds/sidebar.luau`,
  `ui/screens/shell/{page,sidebar,title_bar}.luau`, `ui/ds/composer.luau`,
  `ui/screens/chat/composer.luau`, `ui/ds/icon_svgs.luau`, `ui/ds/avatar.luau`,
  theme `ui/ds/themes/zeron-dark.json` (opaque).
- `public/hero/glyphs.js` (generated by `glyphs.mjs`): the words, as Geist's
  outlines from `apps/zgx/fonts` (the app's own static Regular and Medium),
  shaped with kerning.

Engine facts the port depends on (zgx at the reference's revision):

- The wallpaper's layer is the scene composited, then faded once (a
  smoothstep band the box's height from its foot); the shader reads the
  layer bilinearly at each cell's centre, un-premultiplied; past the layer's
  box it reads clear (the last, partial column of cells holds no glyph).
- Font pixel `max(1, round(1.5·scale))/scale`, cells 6×8 of them, strength
  0.75, threshold 0.22 (Medium, Medium).
- Layers: depth d springs to `d·(14, 9)·(1 − 2p)` for the pointer at p over
  the page; stiffness 140, damping 20, semi-implicit Euler at the app's
  120 Hz (the web steps in the same 1/120 s steps on any display).
- Colours blend in encoded sRGB; `alpha()` is a byte; flat fills and inks are
  painted as their exact composites over their solid grounds.
- Text: line height `ceil(1.4·size)`, baseline `top + (line − 1.3·size)/2 +
  1.005·size` on a whole device pixel, glyphs across on quarter device pixels
  (cosmic-text's `SubpixelBin`), whole pixels below 2x. The place chip's
  names (FadeText) advance by their width rounded to the point, as the app's
  pixels show; nothing in the code says why.
- Shadows: the box offset, covering `0.5·erfc(d/(σ√2))` (zgx's erf
  approximation), σ = blur/2, under the box too.

## Running the rig

Node 22 and Python 3 with Pillow. Once: `npm install` here.

1. A release `zeron-zgx` (any build but the beta reads `ZERON_ZGX_UI` and
   `--inspect`). Its window takes the size saved for its executable's name:
   copy it to a name of its own and save 1176×768 for it, e.g.
   `defaults write zeron-zgx-landing "NSWindow Frame zeron-zgx-gallery" "200 100 1176 768 0 0 1728 1085 "`.
2. `python3 make-ui.py <repo> <scratch>/ui`: a copy of `apps/zgx/ui` with
   `landing_hero_fixture.luau` (shell_fixture with a first-time user's data:
   one device, one project `hello-world`, no chats; zeron-dark, opaque; the
   Parallax scenes plugin as the wallpaper under ASCII, Blossom). A release
   build loads no dev plugins, so the plugin's `Scene` is built in the page's
   background place by the plugin's own code.
3. `python3 reference.py <zeron-zgx-landing> <scratch>/ui <out> "rest=0.5:0.5,tl=0:0,br=1:1"`:
   one window, a scratch HOME and data dir (never `~/.zeron`), `ZGX_CHECK=0`,
   no engine, PATH without the user's tools (no keychain prompts); sets the
   page's pointer states, waits for the springs, takes zgx's inspect
   snapshot of the root, quits. `MOTION=0:0` instead samples the layers'
   boxes from the tree as fast as it can for 1.2 s (`motion.json`).
4. `QUERY=lights=0 node capture.mjs <out> "rest=0.5:0.5,tl=0:0,br=1:1"`: the
   hero at 1176×768, 2x, the same poses (the app's snapshot has no traffic
   lights: they are native views).
5. `python3 compare.py <native> <web> <out> rest,tl,br --region …`: mean
   absolute error per channel, share of pixels off by more than 8 and 32,
   PSNR; side-by-side and difference pictures.
6. `node motion.mjs <native>/motion.json <out>`: the web's frames against
   the spring model, and the app's samples against the same model.
7. `node page-check.mjs <out>`: the landing page itself: desktop (drawn,
   follows the mouse), a 390-wide phone (fits, no sideways scroll, scroll
   frame times), Reduce motion (a still), no WebGL (the still picture).

`node glyphs.mjs` regenerates `public/hero/glyphs.js` when a word changes.
The still (`public/assets/hero/new-chat.webp`, and `new-chat.jpg` for link
previews) is `node capture.mjs <out> "still=0.5:0.5"` (with the lights),
then `cwebp -q 90 -m 6` and `sips --resampleWidth 1600`.

## Results (Nov 11 2026, M4 Pro, zgx 0bce8ef43 build, headless Chrome)

Window 1176×768 at 2x, mean absolute error of 255 per channel:

| pose | window | title strip | sidebar | wallpaper | composer |
|---|---|---|---|---|---|
| rest (0.5, 0.5) | 0.21 | 0.02 | 0.09 | 0.26 | 0.18 |
| top-left (0, 0) | 0.22 | 0.02 | 0.09 | 0.28 | 0.17 |
| bottom-right (1, 1) | 0.21 | 0.02 | 0.09 | 0.27 | 0.17 |
| (0.25, 0.75) | 0.21 | 0.02 | 0.09 | 0.27 | 0.17 |

0.3–0.4% of pixels differ by more than 8, 0.1% by more than 32; PSNR 43–44 dB.
Pictures: `results/side-*.jpg` (app | web | difference ×8), `results/crop-*.png` (2x, unscaled).

Motion: every web frame is a step state of the 120 Hz spring model (largest
gap 1e-8 pt); the app's layer positions, sampled 1,805 times over 1.2 s, sit
on the same model in 10,821 of 10,830 rounded readings.

What's left, and why it can't go:

- Glyph edges: the app rasterizes Geist with swash, the web fills the same
  outlines with Skia. Words differ by 1–2.5 of 255 on average, at stroke
  edges only.
- The ⌘ in the shortcut hints: Geist has none; the app takes SF's (macOS's
  `.SF NS`, first in its fallback list). SF can't be shipped on the web, so
  the hint uses the visitor's system ⌘ (SF on a Mac) fitted to SF's glyph
  box; the browser's SF is a different optical size (strokes a little
  heavier). Elsewhere it's that system's ⌘.
- A few dozen ASCII cells whose brightness sits on the 0.22 threshold flip
  glyph (8-bit texels, GPU filtering), mostly in the faded lower half.
- The traffic lights are native in the app (not in its snapshots); the page
  draws macOS's at their place and size.
