Clients can send about twice the limit if they time it around a window boundary. Find out why and fix it.

Found it. estimate() weights the previous window by Math.floor(1 - into), and that is 0 the moment a new window starts. One millisecond after the boundary the last window's requests stop counting, so a client that fills a window right before it ends can fill the next one right after.
