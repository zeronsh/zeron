# Zeron's words in other languages

Zeron's zgx interface speaks English and Simplified Chinese. The choice is in Settings → General → Language: System (the Mac's preferred language), English or 简体中文. It's kept across launches and applies at once.

It runs on zgx's own i18n (zgx docs: `docs/i18n.md`, `docs/reference/text.md` "Localized messages"): `ui.i18n`, `ui.t`, `ui.locale`.

## Where things are

| | |
|---|---|
| `ui/locales/en.json` | The source: every message, in nested keys by area (`settings.general.*`, `ds.file_tree.*`, `shell.sidebar.*`…), ICU MessageFormat. |
| `ui/locales/zh-Hans.json` | Simplified Chinese: the same keys. |
| `ui/ds/locale.luau` | Loads the catalog (the design system's first module, so a module can make a message as it loads), and the time and date helpers: `ago_short` ("5m"), `ago` ("3 hours ago"), `elapsed` ("1h 5m"), `date`, `month_day`, `weekday`, `clock`, `exact`. |
| `ui/screens/language.luau` | The language chosen (`settings_language`, persisted) and the effect that asks for its locale. The app's alone: a plugin's VM never sets it. |
| `tools/i18n.py` | `merge` (add keys), `apply` (a translation), `check`, `pseudo`, `keys`. |
| `src/i18n_tests.rs` | `cargo test --bin zeron-zgx i18n_tests`: every literal `ui.t` key is in every locale, every message parses, translations name English's arguments. |
| `ui/tests/language.test.luau` | Switching language live, and back; search by a Chinese word. |

The catalog is turned on with zgx-script's `i18n` feature (Cargo.toml), which gives each locale CLDR's plural rules and number formats. Dates aren't ICU's (`i18n-dates` is off): month and weekday names are `select` messages (`time.date`), which keeps ICU's date data out of the binary.

## Writing text

```lua
ui.text { ui.t("settings.general.language.label") }         -- follows the locale
ds.Button { ui.t("common.cancel") }
ui.t("ds.file_tree.copied", { n = count })                  -- {n, plural, one {…} other {…}}
description = function() return ui.t("k"):get() end         -- a string, still following
tooltip = ui.t("k"):get()                                   -- read as it's built
```

Rules (each one learned the hard way):

- **A message is userdata.** Never put one in `ui.state`, `ui.persist`, `ui.shared`, a state's table, or anything compared, sorted or used as an id: state refuses it. A page's `TITLE`, ids, routes and command ids stay plain strings, translated where they're drawn.
- **`:get()` freezes the text unless it's read in a function or computed.** At module load, or in a component's one-time setup, it keeps that locale's text.
- **Some props take only strings:** `tooltip`, `ui.command`'s `title` and `menu`, and a select's option labels (give `options` as a function returning `label = ui.t(k):get()`: it follows). See below for what that means for a language change.
- **English stays as written:** a message's English is the literal it replaced, so tests that match English keep passing.
- **Keys first:** add keys with `python3 tools/i18n.py merge <fragment.json>` before the code that uses them (a missing key shows the key itself). It takes a lock, validates ICU, and puts each new key into every translation in English until it's translated, so `zgx lint` (`i18n-missing`) stays clean.
- **Count with plurals** (`{n, plural, one {# file} other {# files}}`), and build sentences with placeholders, not concatenation. Pass numbers that mustn't be grouped (years) as strings.
- **Settings search** (`screens/settings/search.luau`) takes messages for titles, sections and terms, read in the locale shown as it searches. Each locale's `*.terms` keep the English words beside its own, so either finds a setting.

## Translating

A translation is a fragment with the source's keys: `python3 tools/i18n.py apply zh-Hans <fragment.json>` refuses unknown keys, messages that don't parse and placeholders that differ, and applies nothing until all is right. `check` lists what's still English (`I18N_VERBOSE=1`).

The Chinese was written by a GPT-6.1 Terra chat, in batches by area, against a glossary (product names stay English: Zeron, Appshots, GitHub, Cloud, Claude, Codex…; session 会话, chat/thread 对话, agent 智能体, panel 面板, project 项目, worktree 工作树, template 模板, plugin 插件, provider 提供方, copy 拷贝, Trash 废纸篓).

A new language: add `ui/locales/<locale>.json` (named by BCP 47: `ja`, `zh-Hant`), fill it with `apply`, and list it in `screens/language.luau`'s `LANGUAGES`, in its own words.

## Checking layout

`python3 tools/i18n.py pseudo` writes `ui/locales/en-XA.json`: every message accented and 40% longer, in brackets. Ask for it (`ui.locale:set("en-XA")`, or `settings_language` set to `"en-XA"`) and anything unaccented wasn't extracted, anything without its closing bracket is cut off. It's for checking only: delete it after.

Offscreen pictures: `src/audit_shots.rs` (`AUDIT_TEXT_LANGUAGE=zh-Hans` sets the text language, which picks the faces Han characters draw in).

## What doesn't follow a language change at once

- **The menu bar:** `ui.command` titles are strings read as the scripts load, and zgx-desktop finds the Edit, View and Window menus by their English names. Items change at the next launch, the menus' own names stay English. The Language row says so.
- **Tooltips:** strings only, so the next time their node is built.
- Both are asked of zgx in `zgx-asks/i18n-message-props`.

## Chinese and the font fallback

On macOS 26+ PingFang (the system's Chinese face) holds its outlines in Apple's `hvgl` table only, which zgx's rasterizer can't draw; on zgx before PR #1340 (`c9d85c6`, Zeron's pin) Chinese draws as blank space. zgx #1340 (7b6e0d517) passes such faces for the next one (STHeiti), and #1342 (944fa878d) draws `hvgl` faces through Core Text, so Chinese takes PingFang at Regular weight, matching the Latin beside it. Both verified on macOS 27: Zeron's Settings and palette draw in Chinese with the layout intact. Moving Zeron's pin to 944fa878d or later is all that's left (`zgx-asks/cjk-font-fallback`). Zeron draws no fonts of its own around it.

## Plugins

- **Zeron's words in a plugin:** the design system lent to a plugin shows Zeron's words in the language chosen, from the plugin's first load. zgx keeps one catalog per host and runs plugins' scripts before the app's, so `lend_design_system` (src/plugins/mod.rs) has the host load ui/locales itself (zgx's `ScriptHost::i18n`), before any script runs, with no script of its own (a plugin loaded would make every reload a full one). In the design system, text goes through `locale.t`/`locale.s` (never `ui.t` directly): in a VM with no catalog (a bare test host) they give the English from `ds/locale_en.luau`, which `tools/i18n.py merge` makes from en.json.
- **A plugin's own words:** `locales/<locale>.json` in its folder, shown with the SDK's `zeron.t`/`zeron.s` (docs/plugins.md, "Translations"). The bridge reads them as the plugin loads (src/plugins/locales.rs) and shares them with that plugin alone (`plugin.<id>.locales`). The app shares the locale it shows as `zeron.locale` (screens/language.luau), which the SDK follows: a plugin's VM can't follow `ui.locale` as it changes. Plurals use English's rules there (enough for English and Chinese), formatted by `locale.format`. New plugins are scaffolded with `locales/en.json` (crates/engine `plugins/scaffold.rs`). Example: `plugins-dev/session-words`.
- Tests: `cargo test --bin zeron-zgx a_plugin_s_own_words a_plugin_without_locales the_design_system_lent locales::tests`.

## Rust's words

zgx's catalog lives in the script host and isn't reachable from Rust (`Locales` is crate-private), so text the Rust side makes stays English for now:
- errors shown in the UI: `src/files.rs` (images, folders, names), `src/appshots/` (capture errors), `src/terminal.rs`, `src/images.rs`, `src/projects.rs`, `src/plugins/*` (consent, templates, settings, elements);
- default titles: `src/sessions.rs` "New chat", "New side chat";
- `src/chat.rs`'s "Allow this?" and "Updated the plan";
- the menu item `src/main.rs` "Use Zeron's Template".

The way through, when it's worth it: Rust returns a key and its arguments (`{ key = "files.errors.too_large" }`) and the script shows `ui.t(key, args)`. Or zgx exposes `ScriptHost::i18n()` and Rust formats messages itself.
